## Orchestrator review (Opus, 2026-10-12) — verified, plus four changes

Read every hunk against the code. The diff is correct: the `Profile` template split moves no line of
real work, the off instantiation's `NoClock` is an empty type so even the constructor's clock read is
gone, the four laps are inside the island's own whole-island stopwatch, and the phases sum under it
(5271 against 5273 us on run 2; 1087215 against 1087398 ns on the Debug fixture). Changes made on
top:

1. **`IslandSolveCost::constraints` is one entry per MANIFOLD, not per point** — `world.cpp` ~1278
   pushes one `ContactConstraint` per manifold and each carries up to four points. The comment said
   "(points)" and was wrong; corrected, because this is the number anyone will price a solver change
   off. The 1348 of the worst step is therefore up to 5392 points.
2. **Deleted the vacuous profile-off phase loop.** Profile-off publishes no entries, so a loop of
   `CHECK(c.warm_ns == 0)` over it runs zero times and reports PASS having inspected nothing — the
   house failure mode. The `empty()` assertion is the claim that can fail; the comment now says why
   the zero-check is expressed as emptiness.
3. **The sample's hardcoded `/ 8` now says where the 8 comes from.** `kVelocityIterations` lives in a
   private header the sample cannot include, so a change to the constant would silently misprice the
   one number this line exists to report.
4. **`docs/perf/README.md` gains the finding**, the consult record, and the next brick's two tiers.

### The `--ticks 900` gate failure was the SPEC's error, not the branch's

The spec asked for `--headless --ticks 900`, which fails "collapse: most of the block is still
standing" — and does so on unmodified `main` too, as the agent checked. The claims are end-state
claims about a scripted beat: 900 ticks runs long past it. **Bare `--headless` on this branch: exit
0, all 29 claims hold.** That is the gate, and it is green. Recorded in `CLAUDE.md` beside the
m19.4 mirror image of the same mistake (`--ticks 60`, too short, five innocent failures).

### What I did not re-run, and why

The two profiled 600-frame runs were not repeated. They agree on the quantity being measured (the
~94 % velocity share) and disagree only on which step was worst, with run 1 visibly perturbed on
`frame` p99 — so a third run would buy a tie-break on a number this brick does not claim. No
unprofiled control was taken in this sitting either, so the instrument's own cost is bounded by
run-to-run spread rather than isolated; `docs/perf/README.md` says so rather than implying a
measured overhead.
