**INFERRED — Ranked by engineering effort:**

1. **Try a fixed 4/1 iteration budget. Cost: minutes to implement; substantial validation is the real expense.**

   Keep canonical traversal, warm starting if already present, and all contact points. Change only the two fixed iteration counts. This approximately halves *iteration work*, not necessarily the complete solve: with non-iteration overhead \(H\), the estimate is \(T_\text{new}=T/2+H/2\).

   **Quality:** fewer velocity iterations generally mean less complete load propagation through stacks, more apparent softness/slippage, and potentially different collapse timing. Fewer NGS iterations leave more positional error. This is an experiment with a quality tradeoff, not a free optimization. Warm starting can help settled contacts, but cannot establish equivalence during newly forming rubble contacts. [Solver2D](https://box2d.org/posts/2024/02/solver2d/)

   **Determinism:** compatible with fixed-count, worker-independent execution. The new version need not match the old version’s world hash. Validate penetration, stack drift, collapse progression, and sleeping—not just hash agreement between workers.

2. **Prepare velocity constraints once; reuse genuinely invariant quantities across all eight passes. Cost: roughly one to several days, conditional on what already exists.**

   Look specifically for repeated effective-mass calculation, world-space inertia transforms, contact lever arms, tangent-basis construction, material combination, and dense-index lookup inside the velocity sweep. Store the necessary values in compact constraint records; keep sequential impulse updates and contact ordering unchanged.

   **Quality:** unchanged if the cached values truly remain invariant during the velocity solve and arithmetic is preserved. Do **not** extend this blindly to NGS: position/orientation updates can invalidate geometry and effective masses.

   **Determinism:** compatible; potentially preserves the existing hash as well. Avoid arithmetic reassociation or a different scalar/SIMD path selected by worker count.

   A halving is plausible only if substantial repeated work exists. Neither SoA storage nor the quoted timings establishes that. If preparation is already good, this candidate has little headroom.

3. **Deterministic graph-colored intra-island solving. Cost: several days to weeks including validation.**

   Traverse constraints canonically and assign the first available color whose constraints touch no common writable body. Solve colors in fixed order, with parallel chunks inside each color and a barrier between colors. Keep manifold points together when their processing shares state. Read-only static bodies need not create conflicts. Apply the same schedule at every worker count, including one. [Box2D’s graph-coloring explanation](https://box2d.org/posts/2024/08/simd-matters/)

   **Quality:** retains Gauss–Seidel updates between colors, but changes ordering and therefore finite-iteration convergence. Stiffness can improve or worsen; collapse trajectories can change. It avoids the additional convergence penalty of replacing PGS with simultaneous Jacobi updates.

   **Determinism:** achievable with canonical coloring, disjoint writes, fixed barriers, and no unordered floating-point reductions. A twofold gain is a target, not a prediction: 1,348 points may produce small batches, and repeated barriers can dominate. SIMD within colors is a subsequent investment.
