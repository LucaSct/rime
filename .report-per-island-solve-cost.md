# Per-island solve cost (measurement brick)

Branch `perf/per-island-solve-cost`. No solver, partition, sleep or dispatch change; no docs change.

## What changed
- `engine/physics/include/rime/physics/world.hpp`: `IslandSolveCost`, new `WorldStats` fields
  (`island_solve_ns_total`, `largest_active_island_solve_ns`, `largest_island_prev_bodies`,
  `largest_island_membership_changed`), `set_island_profile_enabled()`, `island_profile_enabled()`,
  `island_solve_profile_last()`. No existing field changed meaning.
- `engine/physics/src/world.cpp`: `Impl` profile state; `solve_island_timed` wrapper around the
  UNCHANGED `solve_island`; the dispatch is now a generic lambda `dispatch_islands` handed either
  callable; sequential post-join collection in the stats tail.
- `tests/physics/stats_test.cpp`: `island profile: ...` test case.

## Zero cost when off
The only check is `const bool profile_islands = p.island_profile_enabled;` once per step, before the
dispatch, picking which callable `dispatch_islands` receives. Off, `solve_island` itself is passed:
no clock call, no slot write, no branch, no allocation (slots are `assign`ed only when on). The
`parallel_for` call site is the same code instantiated for a different callable type.
Clock: `core::Stopwatch` (profile.hpp, `steady_clock`). Each island is timed on the thread that
solves it and writes `island_solve_slots[k]` only (64-byte aligned slots, pre-sized by
`island_count`); no mutex, atomic or shared counter. Collection is sequential after the join.

## Definitions worth knowing
- `largest_active_island_solve_ns` is the MAX solve time over active islands (the true serial tail
  in time), which need not be the island with the most bodies. serial fraction = that / total.
- Merge signal: FNV-1a over the largest-by-bodies active island's dense body indices + its count,
  compared with the previous PROFILED step's. Exact up to a 64-bit collision for "a different set of
  bodies is the big island". It cannot say why: merge, wake of sleeping neighbours, split, a swap to
  a different island, and create/destroy between steps (dense indices shift) all read as changed.
  `largest_island_prev_bodies` vs `largest_active_island` gives growth vs shrink. First profiled
  step, a gap in profiling, or a step with no active island reports changed=false.

## Measurements (MEASURED; Debug `dev` preset, sequential solve, mean of 120 steps after 60 warmup)
Scene: 6 separated unit-box columns, sleeping off, 49 bodies.

| island | bodies | constraints | solve_ns | ns/body |
|---|---|---|---|---|
| 0 | 24 | 24 | 1132538 | 47189 |
| 1 | 12 | 12 | 557423 | 46452 |
| 2 | 6 | 6 | 269503 | 44917 |
| 3 | 3 | 3 | 118349 | 39450 |
| 4 | 2 | 2 | 73399 | 36699 |
| 5 | 2 | 2 | 67041 | 33520 |

Serial fraction 0.5106, implied ceiling 1.959x (MEASURED for this scene). Body share of the largest
island is 24/49 = 0.490, so here time share is slightly ABOVE body share.
Cost vs size (INFERRED, six points, one scene, Debug build): ns/body rises mildly with island size
(33.5k to 47.2k per body across a 12x size range), so cost looks close to linear, slightly
superlinear (roughly exponent 1.05 to 1.1 by eye). Not a scaling study. One-body-per-constraint
columns only (chains), so it says nothing about densely connected piles with many constraints per body.
These are Debug numbers; do not compare absolute ns to the Release 8.5 ms p99.

Merge signal: 0 of 120 steady steps flagged changed (MEASURED). A box set overlapping the foot of
the big column: largest 24 -> 25 bodies, changed=1, prev_bodies=24 (MEASURED).

Determinism: world_hash identical for profile off, on (sequential) and on (4-worker job system) after
180 steps (MEASURED, asserted).

## Contradictions with the spec
- The spec asks for `largest_active_island_solve_ns` as "the serial tail in TIME"; I made it the max
  over islands, not the time of the biggest-by-bodies island (the entries carry both).
- The test scene is chains of boxes, not the 602-of-656 pile of the real sample, so the 1.96x
  figure is NOT a statement about that sample. Next step is enabling the profile there.
- `scripts/build.sh --cpp-only` exited 8 on the first run only because my merge-step test box
  touched without penetrating (no contact); fixed in the test, no assertion loosened.
- No NEW translation unit exists; clang `-fsyntax-only` was run on the two touched TUs (exit 0).
