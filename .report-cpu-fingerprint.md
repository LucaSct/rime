## Orchestrator's verification pass (Opus, 2026-10-11)

Verified by measuring the sampler rather than by reading it, which is the only reason the following
was found.

**The sampler was spinning at 99.70 % of one core, sampling at 190 Hz instead of 20 Hz.** Measured:
997 ticks over 10 s, 1901 samples. The cause is a subtle trap worth keeping: the 50 ms wait was
`read -t 0.05` on a descriptor from `exec {idle}<> <(:)`, and a process substitution is a pipe that
is **already at EOF** — a timed read on an EOF pipe returns *instantly*, so the wait was a no-op.

Why that is serious rather than merely wasteful: this sampler exists to describe a **CPU-bound**
benchmark, so a spinning sampler competes for the exact number it reports. And the blast radius was
checked rather than assumed — a subshell's `comm` under this script is **`bash`** (verified with a
throwaway script named `perf.sh`), which is **not** in `$foreign_mine`, so `foreign_compare` would
have flagged `bash at ~100% CPU`, failed the run and refused to file. **Every** perf run from here on.
Loud rather than silent, but broken.

Fixed with a real `mkfifo` opened read-write (`<>` keeps a writer open, so a read blocks for the full
timeout), unlinked immediately with the open descriptor keeping it alive. The reason is in the
comment, because the broken version is the one a reader would naturally write.

| | before | after |
|---|---|---|
| CPU | **99.70 % of one core** | **0.80 %** |
| rate | 190 Hz | **19.9 Hz** (target 20) |

0.80 % is also comfortably under `foreign_compare`'s 50 % competitor threshold.

**Gates re-run after the fix.** `bash -n` exit **0**. `scripts/perf.sh --self-test` exit **0**, all
cases passed. A 120-frame run exit 1 (`the-block` always exits 1 on its budget gate) emitting:

    cpu: AMD Ryzen 9 9950X3D 16-Core Processor, governor performance, 2 L3 domain(s),
         busiest core 5663.5 MHz median, 1.0% spread over 32 samples

and **no `DID NOT STAY IDLE` and no `at N% CPU` line**, which is the decisive check: the watcher stays
quiet with the fixed sampler.

**JSON verified.** Valid, `cpu` present, and all nine pre-existing top-level keys survived
(`schema, run, machine, distributions, passes, worst_frame, ledger, integrity, gpu_clocks`).
`l3_domains: 2` with `["0-7,16-23", "8-15,24-31"]` — the decisive field, and the first time any report
has carried it. The not-measured path was confirmed in the code: `inject_cpu_info`'s `nz()` emits
`null` for an empty value, matching the existing `"stable": null` convention, so an absent fingerprint
reads as *not measured* rather than as a zero.

**Accepted as reported:** `shellcheck` is genuinely not installed (the agent said so rather than
claiming the gate passed). The `/proc/cpuinfo` fallback is still **unexercised** — inferred only, since
this box has cpufreq. The GPU's `stable=false` on a short run is pre-existing behaviour on an unpinned
box, not this change.
