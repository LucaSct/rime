# Build `samples/solver_bench` — a fixed-workload physics solver benchmark

The design below is DECIDED. Build exactly this. Say plainly what contradicts it rather than
working around it. "I could not determine this" is an acceptable answer for any item.

## Why it must exist (read this; it determines what a correct result looks like)

`samples/99-the-block` cannot measure a solver change that alters floating-point rounding. Measured
2026-10-12 and written up in `docs/perf/README.md`: a perturbation that is mathematically a NO-OP
(normalising an already-unit quaternion) changed the collapse enough to fail 2 of the sample's 29
`--headless` claims, and a different non-bit-identical solver variant failed 2 OTHER claims and moved
the workload with it — 22 % fewer bodies, 31 % fewer broadphase pairs. A perf A/B between two such
variants is therefore not a comparison of solver cost; it is a comparison of two different
simulations. This bench removes the chaos so solver cost can be priced.

**The one property that matters: the comparable number must come from a state that is IDENTICAL
under any solver.** That is step 1 from a hard-placed configuration — identical initial poses give
identical broadphase pairs and identical manifolds, by construction, whatever the solver does
afterwards. Everything else in this bench is context.

## What to build

Public API only (`rime/physics/world.hpp`); do not include anything from `engine/physics/src/`.

1. **Deterministic construction, no settling.** A large static box as the floor, then a lattice of
   dynamic bodies placed at hard-coded positions with a small deliberate overlap (a few mm, inside
   the penetration slop's order) so that step 1 already produces many contacts. Vary poses with a
   fixed LCG seeded from a constant (`--seed` may change it; the default must be fixed). No
   `std::random_device`, no clock, nothing that varies between runs.
2. **Mixed shapes, and this is not optional:** roughly 60 % boxes and 40 % convex hulls. A hull's
   `inertia_principal` is a non-identity rotation while a primitive's is identity, and the inertia
   path is exactly what this bench exists to price — an all-primitive pile would measure the wrong
   code.
3. **Targets at step 1: at least 300 dynamic bodies in ONE island and at least 1000 contact
   manifolds** (the real tail step is 362 bodies / 1348 manifolds). Tune the lattice until it hits
   that. Print the achieved numbers. If construction cannot reach them, exit non-zero saying so
   rather than reporting a smaller workload as if it were the intended one.
4. **Sleeping disabled** (`set_sleeping_enabled(false)`) so the island stays awake, and **no job
   system** — leave it unset so the solve runs on the calling thread. The pile is one island, so
   island-level parallelism cannot divide it anyway (that is #312's measured result); say so in a
   comment.
5. **Island profiling on** (`set_island_profile_enabled(true)`), and read the per-island table with
   `island_solve_profile_last()`. `IslandSolveCost` carries `bodies`, `constraints`, `solve_ns`,
   `warm_ns`, `velocity_ns`, `store_ns`, `position_ns`. Note in a comment that `constraints` counts
   contact MANIFOLDS, not points.

## What it prints

Per repeat, build a FRESH world and step it `--steps` times (default 32), recording for each step:
manifolds, constraints, active islands, and for the largest island by `solve_ns` its bodies,
constraints and the five timings.

Then print, in this order:

1. **The headline: STEP 1**, aggregated over the repeats (median, min, max):
   `solve_us`, `velocity_us`, `us per constraint` (velocity_us / constraints), `us per velocity
   iteration` (velocity_us / 8 — the 8 is `kVelocityIterations` from a private header the bench
   cannot include, so hardcode it and say in the comment that it must be changed with it), and the
   step-1 `bodies` / `constraints` themselves, which must be identical across repeats.
2. **The step series** of one representative repeat, as a small table, so two runs can be diffed by
   eye.
3. `world_hash()` after step 1 and after the last step, for the first repeat. A bit-identical change
   leaves both unchanged; a non-bit-identical one visibly moves them. This is the bench's own
   determinism witness.
4. **One machine-readable JSON line** with all of the above, prefixed `solver_bench_json: `.
   **Do not write any file. Never write into `docs/perf/`.**

CLI: `--bodies N`, `--steps N` (default 32), `--repeats R` (default 5), `--seed N`, `--json-only`.
Exit 0 on success; non-zero only if construction missed the targets.

## Gates — run each as its own command and check `$?`. Never grep a build's output for errors.

```
cmake --build --preset dev
cmake --build --preset release
clang++ -fsyntax-only <flags from build/dev/compile_commands.json for the new TU> samples/solver_bench/main.cpp
~/.rime-tools/bin/clang-format -i samples/solver_bench/main.cpp
build/release/bin/solver_bench
```

A new translation unit MUST get the `clang++ -fsyntax-only` pass: every build in CI except one is
GCC or MSVC, so a GCC-only loop cannot see a Clang error. Reconstruct the flags from
`build/dev/compile_commands.json` after the first configure so the include paths are real.

**Do not run the full test suite.** This adds a sample and touches no engine code; the targeted
proof is that the bench builds, runs, and hits its targets.
