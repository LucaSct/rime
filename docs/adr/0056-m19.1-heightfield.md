# ADR-0056 (m19.1): The terrain heightfield — a quantised cooked format and a grid-native collision shape

- Status: Accepted (number provisional — renumbered at merge)
- Date: 2026-09-30

## Context

M19 is terrain (ROADMAP, the M18 row: "Terrain's heightfield, collision, splat blending and
streaming are M19"). Nothing in the engine can represent a terrain today: the ground is a tiling
plane (`engine/ground`), physics has no static-mesh shape, and the asset pipeline has no height
data. M19.1 is the milestone's first brick and deliberately CPU-only — the data every later brick
reads (rendering, splat blending, streaming all consume the same grid), and the collision that
makes it a place a body can stand. Two decisions have to be pinned before anyone builds on it:
**what the cooked heightfield is**, and **how physics collides with it** without bending
ADR-0026's determinism contract or its broadphase.

The forces:

- **Terrain sources are 16-bit integers.** Every terrain tool (World Machine, Gaea, Houdini, DEM
  exports) writes 16-bit grayscale PNG or raw. Anything else the cook stores is a conversion.
- **Terrain is the largest data set a world streams**, so bytes per sample matter.
- **Rendering and physics must agree on the surface.** A non-planar grid cell has two different
  triangulations; if the renderer splits it one way and physics the other, balls visibly float or
  sink. That choice cannot be left to whichever reader is written first.
- **A heightfield is not convex.** The narrowphase (GJK/EPA/clipping) and every convex query run on
  support functions a terrain does not have. It is, however, the most structured non-convex shape
  there is: "which triangles are near this point" is a `floor()`, never a tree search.
- **The broadphase is dual AABB trees (ADR-0026).** A kilometre-wide static AABB is a leaf whose
  bound contains most of the world.

## Decision

### 1. The cooked format: RMA1 kind 9, quantised u16 samples, the triangulation in the header

A new asset kind (`AssetKind::Heightfield = 9`) in the existing RMA1 container, with a reflected
52-byte header record (`HeightfieldHeaderV1`, whose `type_hash` is the schema fingerprint both
languages pin) that **leads with its own payload version** — the container version guards the
envelope; this one guards the heightfield layout, so a v2 payload is refused as
`UnsupportedVersion` by name. Byte layout: `tools/asset-pipeline/FORMAT.md`.

- **Heights are u16 with a scale and offset in the header**:
  `height = offset + scale * sample`. Chosen because (a) it is what sources are, so the cook copies
  samples verbatim — exact, and deterministic by construction (no float touches the bulk of the
  payload); (b) half of f32; (c) *uniform* precision, unlike f16 whose step grows with altitude;
  (d) the renderer can upload the samples as `R16_UNORM` and apply the same scale/offset, so the
  surface drawn and the surface collided with come from the same integers. The cost is a bounded
  vertical error of half a step, `(height_max − height_min) / 131070` — 7.6 mm over a 1 km range.
- **The triangulation is a header field** (`DiagonalMinToMax = 0`: every cell split from sample
  (i, j) to (i+1, j+1)). One value in v1; a later per-cell best-fit diagonal is an appended value,
  and the reader rejects values it does not know.
- **Writer of record: `tools/asset-pipeline/src/heightfield.rs`** (`rime heightfield <src>`), from a
  16-bit PNG or raw `.r16` plus a `<src>.toml` sidecar (world size, height range, origin; nine
  numbers, parsed by hand rather than adding a TOML dependency; unknown or duplicate keys are
  errors). 8-bit sources are refused, not widened.
- **The C++ reader** (`read_heightfield`) validates every field and the sample range exactly (the
  header's recorded min/max is a comparison-only reduction, so a sample outside it can only be
  corruption), and **tallies every refusal by reason in a caller-owned `AssetRejectCounters`** —
  caller-owned, not a process-wide static, because loaders run on the job system and a global
  mutable tally is the hidden shared state the threading guardrail forbids.

### 2. The collision shape: a world-owned store, static only, one broadphase leaf per tile

`ShapeType::Heightfield` references a **world-owned store** (`register_heightfield` →
`HeightfieldId`), exactly the hull/compound storage answer (ADR-0027/0028) for the same reason:
`ShapeDesc` stays a flat POD. The store keeps the samples quantised (one multiply-add to read a
height). Registration takes the same u16 + scale/offset form the asset carries, so a loaded tile
registers without a conversion pass — physics does not depend on `engine/assets`. A heightfield body
must be **static**; the grid may be posed (translated and yawed; "up" is local +Y).

**Broadphase: one leaf per tile in the static tree, accepted for now.** Its bound is the tile's full
box (extended `thickness` below the lowest sample). This is acceptable because (a) the static tree
is only ever *queried* by movers — it is not rebuilt, and a big leaf near its root costs each query
one extra node test; (b) the pairs it produces (every awake body over the tile) are pairs that
genuinely need a terrain test anyway; (c) inside the pair, the grid is its own midphase — the cells
under a body are `floor(aabb / cell)`, O(1), no per-triangle tree. The scaling answer is **tiles**:
streaming (a later M19 brick) registers terrain as many tile bodies, each with its own bounded leaf,
so the tree sees a grid of modest boxes rather than one continent. What is *not* done: splitting one
registered heightfield into several proxies, which would break the proxy↔body 1:1 model ADR-0028
chose — tiles make it unnecessary.

**Raycast: a 2-D DDA grid walk with exact per-triangle roots.** Clip the ray to the tile box, walk
the cells its XZ projection crosses (Amanatides & Woo; crossing t recomputed from the cell index each
step, so error cannot accumulate), split each cell's segment at the diagonal, and on each piece solve
the ray's height above that triangle's plane — linear in t, so one division. First hit in walk order
is the nearest. A seam rule (above at the end of one piece, below at the start of the next ⇒ hit at
the seam) makes the walk watertight without epsilons. The surface is **one-sided for rays** (a ray
starting beneath it never hits it on the way out — `ray_vs_box`'s "origin inside" rule).

**Contacts: one-sided per-triangle tests, grouped into patches.** Cells under the body's bound are
visited in fixed ascending order; each triangle is tested with a routine per shape family:

- sphere — Ericson's closest-point-on-triangle; from above, the radial direction; sunk below the
  plane, only over the triangle's interior and only straight back along its normal;
- capsule — its two end spheres plus the core segment's closest approach to each triangle edge;
- box / convex hull — **the triangle is always the reference face**: the body's most-opposed face is
  clipped by the triangle's three side planes (the M7.11 Sutherland–Hodgman path), plus body
  vertices inside the triangle's prism; depth along the triangle normal;
- compound — each convex child on its own, its index in the manifold's child slot (ADR-0028).

Forcing the triangle normal is the point: GJK/EPA against each triangle as a separate convex solid
produces sideways "internal edge" normals and a box sliding over flat terrain catches on the seams.
Duplicates (a contact on a shared edge or vertex found by every triangle that owns it) collapse by
position + normal. Candidates are then **grouped into at most four patches by normal (within ~3°)**;
each patch is one manifold (reduced to four points by the existing `reduce_manifold`), because one
manifold holds one normal and a ball in a gully touches two walls. A patch is a contact *region*
named by its seed triangle (`Manifold::patch`, `ContactEvent::patch`, and a third field in the
warm-start cache key); flat or planar-sloped ground is exactly one patch.

**Determinism (ADR-0026)** holds by construction: fixed cell/triangle order, first-wins ties,
patches seeded in candidate order, no unordered iteration, contacts built in the sequential
contact stage. `heightfield_test.cpp` asserts `world_hash()` identical for 0, 2 and 8 workers.

**Fallbacks are counted, not silent** (CLAUDE.md guardrail 5's lesson, applied): `WorldStats` gains
`heightfield_patch_merges` (a fifth normal folded into the best-aligned patch) and
`heightfield_ccd_skipped` (a CCD body near terrain with no exact contact — terrain has no
speculative path); `heightfield_query_skips()` counts `shape_cast`/`penetration` skipping terrain.

## Consequences

- Terrain can be cooked, loaded, registered, raycast, stood on and queried with `overlap_sphere`,
  all GPU-free, all in CI. Rendering, splat blending and streaming build on the same asset.
- **Deferred, each counted where it bites:** `shape_cast` / `penetration` against terrain (a
  character controller on terrain needs a per-triangle cast — the next physics brick for M19);
  speculative CCD against terrain (a fast projectile can tunnel through it); per-cell best-fit
  diagonals; terrain holes; heightfield bodies through the ECS `Collider` component; a per-cell
  min/max hierarchy to accelerate long rays over large tiles (the walk is O(cells crossed)).
- The terrain is solid down to `thickness` below its **lowest** sample: something legitimately
  beneath it (a tunnel mesh) inside that band would be pushed up through the ground. A heightfield
  cannot express open space under the surface; that is what other geometry is for.
- `Manifold`, `ContactEvent` and the cache key grew one `u32`; non-terrain pairs carry 0 and every
  pre-existing ordering, key and event is unchanged.
