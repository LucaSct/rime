# ADR-0056: bounded virtual-geometry page streaming — fixed slots, fence-gated residency

- Status: Accepted
- Date: 2026-09-30
- Implements: [ADR-0043](0043-virtualized-geometry-m18.md) gate 5 ("bounded streaming")

## Context

Until M18.5, virtual-geometry residency was a contract (`VirtualGeometryResidency`), not memory:
the visibility pass copied every drawn cluster's bytes into fresh host-visible buffers on every
`declare()`. Gate 5 asks for real, bounded memory: delayed pages and camera teleports keep the
coarse cut without holes, memory plateaus, and submitted pages cannot be evicted.

Two hazards decide the design, and both are timing bugs that look fine on a fast GPU:

1. **Residency on issue.** Recording an upload copy is not the same as having the bytes. If the
   selector sees a page as soon as its copy is recorded, it only works while the copy and the
   draw happen to share a command buffer and nothing is dropped. This is the replication
   guardrail (CLAUDE.md #5) in another costume: a "what they have" fact strengthens only on
   confirmed holding.
2. **Reuse under a reader.** With frames in flight, a slot evicted this frame may still be read by
   a frame the GPU has not finished. Overwriting it tears that frame's mesh.

## Decision

**Policy and memory are separate objects.** `VirtualGeometryPageCache` (CPU-only) decides; it
takes an explicit frame clock — the frame being recorded and the newest *retired* frame — so every
rule is testable deterministically with a fake clock. `VirtualGeometryPagePool` executes it
through the RHI (never Vulkan directly).

**Fixed-size slots in one pool buffer.** Every page occupies one `slot_bytes` slot; a page larger
than a slot is refused at registration. A slot is a whole number of vertices and u32 words, so
shaders address a cluster in the pool with the existing vertex/index-base ABI (ADR-0044) and no
per-frame copy. Fixed slots trade a page's unused tail for allocation-by-free-list and one-for-one
eviction with no fragmentation or compaction.

**Retirement comes from fences, in order.** The pool keeps each frame's `SubmitTicket` and polls
`Device::is_complete` front to back; the watermark stops at the first unfinished frame. A
`submit_blocking` frame is retired when the call returns. An invalid ticket (a submission that did
not happen) abandons its uploads — `is_complete()` answering true for it must not read as "the
copies ran".

**The two rules.** A page becomes resident only when its upload's frame has retired. A resident
page is a victim only if its last *read* has retired, it is not wanted this frame, and no resident
or uploading page depends on it; among those, least recently read-or-wanted goes first.

**A budget that is also the staging segment.** The per-frame upload budget is the size of one
staging-ring segment; frame F writes segment `F % segments` only after that segment's last user
retired. Requests are served in priority order (DAG depth, so the cut sharpens a level at a time)
with head-of-line blocking on bytes, so a large high-priority page cannot be starved by small ones.

**Hole-free by construction.** The permanent coarse cut is uploaded *blocking* at registration
into pinned slots, may depend only on permanent pages, and is never a victim. The selector already
stops at an ancestor whose children are not all resident; the driver counts that as a fallback.
The visibility pass's page-pool mode draws the selected cut verbatim, interior groups included,
because the fallback *is* an interior group.

**Uploads are one RHI call per frame.** `CommandBuffer::copy_buffer_regions` (new) batches every
staging-to-slot copy into one `vkCmdCopyBuffer` with upload-shaped barriers. It is recorded before
the graph executes rather than as a graph pass; the graph has no transfer pass kind yet, and the
copy's own conservative barriers make the bytes visible to every later stage.

Every path that turns a request into not-an-upload has a counter: budget, staging busy, no
evictable slot, dependency pending; plus requests, uploads issued/retired/abandoned, evictions,
fallbacks, and a caller-bug counter for marking a non-resident page as used.

## Consequences

- Pages stream from the asset's already-loaded CPU blob. Disk I/O is a later seam: nothing in the
  cache assumes more than "the bytes are readable when `record_uploads` runs".
- Pool memory is fixed at creation — the plateau gate 5 asks for is structural. Too small a pool
  shows up as `deferred_no_slot`, never as a hole.
- The identity index buffer in pool mode spans every u32 word of the pool (a cluster's
  `first_index` is its word offset in the pool), so it costs as much memory as the pool. It is
  built once per pool size. A per-draw local index scheme would shrink it to one cluster's worth,
  but changes the ADR-0044 vertex-shader ABI and is left for when it is measured.
- Victim search is a linear scan over every registered page, and residency bytes are per asset,
  not per instance. Both are fine at test scale and unmeasured at town scale.
- The GPU-built submission path (M18.3c) accepts `page_pool`, but only the CPU-built path is
  proved against the pool. The resolve pass reads pool-relative bases through the same ABI, but no
  test runs it against a pool yet.
