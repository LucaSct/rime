# ADR-0065 (m19.6): Terrain reads the sky — SH diffuse, a sky-view mirror and an analytic env-BRDF

- Status: Accepted
- Date: 2026-10-05

## Context

ADR-0064 gave terrain the shared GGX BRDF and a metallic/roughness blend, but its ambient term was
a flat constant: a uniform-environment stand-in. A metal has no diffuse, so under that stand-in its
only light away from the sun's highlight is `ambient * f0`. It reads dark, because what makes a
metal look like metal is the environment it reflects. The engine already has a physical sky
(`SkyPass`, m17.7b/m17.7d). Each frame it publishes a sky-view LUT and a nine-coefficient SH
irradiance buffer as a `SkyLightBinding`, and `pbr_forward_shadowed.frag` and `ssr_resolve.frag`
already read them.

## Decision

### 1. `TerrainPass::add` takes the sky as an optional parameter

The sky arrives as a trailing `const SkyLightBinding& sky = {}`, following
`ForwardPbrPass::add_shadowed`, which also takes the binding as a parameter. The default binding,
with every handle invalid, means "no sky". So does a binding with **any** member invalid: it is
treated as no sky as a whole and never mixed with placeholders. In that case the pass binds its
**own** 1×1 dummy LUT and all-zero SH buffer, the pair `SkyPass::empty_binding` provides, owned
here so a caller with no `SkyPass` can still draw. The pipeline gains set-0 bindings 3 (LUT,
CombinedImageSampler) and 4 (SH, storage buffer, `SKY_SH_BINDING`). Both are declared graph
reads, which orders the draw after the bake. The push block stays at 160 bytes.
`sky_bound_draws()` counts draws that used a caller's binding.

**The LUT state contract.** Sampling the LUT leaves it in `ShaderRead`. The caller that owns the
`SkyPass` reports this with `note_skyview_state(ShaderRead)`, just as `SceneRenderer` does for the
background and SSR. `TerrainPass` never sees the `SkyPass`, so it cannot report the state itself.

### 2. Diffuse: the SH replaces the flat ambient one for one

`sky_sh_irradiance(n)` returns the radiance leaving a white Lambertian surface: irradiance that has
already been divided by π. That comes from reading the code, not from a measurement: sky_sh.comp bakes
Ramamoorthi & Hanrahan's A0, A1 and A2 already divided by π (`a0 = 1.0`), so a uniform sky of radiance L
evaluates to L. Those are
the units the flat `ambient` stood in for. So the diffuse term is
`(1 - metallic) * base * sky_sh_irradiance(n)`, with no further 1/π. `pbr_forward_shadowed.frag`
uses the same convention (`albedo * sky_ambient`). That shader does **not** weight by
`(1 - metallic)`, so a metal there still receives sky diffuse. Terrain keeps ADR-0064's weighting.
The difference is recorded here, not fixed here.

### 3. Specular: the LUT along the mirror direction, times Karis' EnvBRDFApprox

The specular term is `env * EnvBRDFApprox(f0, roughness, n·v)`. EnvBRDFApprox is the analytic fit
from Karis' "Physically Based Shading on Mobile" (2014) to the split-sum environment-BRDF table of
"Real Shading in Unreal Engine 4" (2013). It needs no texture, no bake and no binding. `env` is the
sky-view LUT read along `r = reflect(-v, n)`, through `skyview_uv_from_direction`.

- **Below the horizon** the LUT shows the planet's ground as seen from altitude, which is not what a
  terrain reflects. The LUT coordinate's elevation is clamped to the horizon row (`uv.y ≥ 0.5`) and
  the azimuth is kept. Terrain mostly reflects the low sky, and a grazing view of a slope then
  mirrors the horizon glow rather than a dark planet.
- **Roughness.** The LUT has no prefiltered mips. The environment therefore fades from the LUT's
  point sample to the SH's cosine-weighted average, evaluated at `n`, with
  `env = mix(lut(r), sh(n), alpha)` where `alpha = roughness²`. The GGX lobe's angular width grows
  like alpha, not like perceptual roughness: roughness 0.1 stays 99% mirror, 0.5 is a 25% blend and
  1.0 is all SH.

### 4. No sky renders exactly as m19.5

The no-sky branch is ADR-0064's flat-ambient code, instruction for instruction, gated by
`sky_sh_enabled()`. The proof compares against a **frozen copy** of m19.5's `terrain.frag`
(`tests/terrain_render/shaders/terrain_m195_reference.frag`). It is drawn with the engine's own
vertex stage, tile resources and push block, and the two images are memcmp'd. A copy is used
rather than an `#ifdef` variant, because a variant would drift with the live shader. A stored image
is not used either, because it would be a golden image.

## Consequences

- Proofs (`m19.6:`), measured on an RTX 3060 (this workstation has no lavapipe ICD):
  - With no sky argument, and with a caller's `empty_binding()`, the image is memcmp-identical to
    the frozen m19.5 shader, for a metal and for a dielectric.
  - Swapping the sun elevation from 1.2 to 0.08 rad moves a smooth metal 0.324 relative and a rough
    dielectric 0.222.
  - With the sun and the ambient both at zero, the metal is black without a sky and lit at
    16384/16384 pixels with one.
  - With the sun off, two dielectric base colours differ only through the SH diffuse.
- **The bit-identity anchor is sensitive to driver code generation.** Deleting a line from the
  *sky* branch (a falsification) changed one or two no-sky pixels by one half-float ULP (1.2e-4).
  The anchor holds for the shader as written. A future edit to the sky branch can still turn it
  red with no logic change, and its failure message reports the pixel count and the worst
  difference so that case can be recognised. If it becomes a nuisance, the fix is a separate no-sky
  pipeline compiled from the m19.5 source, not a tolerance.
- The flat `TerrainLight::ambient` is ignored whenever a live sky is bound. The sun is still
  `TerrainLight`'s, not the sky's: the caller couples the two, as `SceneRenderer` does through
  `use_scene_sun`.

## Known limits

- **No prefiltered radiance.** At mid roughness the result is a sharp sky dimmed and mixed with a
  blurred one, not one properly blurred sky.
- **No sky occlusion.** A valley floor reflects sky that its own walls hide, and the SH lights
  slopes the terrain shadows. Terrain therefore reads too bright in concave relief.
- **The horizon clamp.** It brightens grazing reflections that should show the terrain itself.

## Deferred

- Prefiltered environment radiance (a mip chain or a small cubemap off the LUT).
- Specular and sky occlusion (horizon maps or a heightfield AO bake).
- Per-layer textures (still ADR-0064's deferral).
