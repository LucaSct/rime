# ADR-0067 (m19.8b): Releasable, generation-checked asset ownership — the AssetServer streams terrain

- Status: Accepted
- Date: 2026-10-05

## Context

`AssetServer` (M6.5, ADR-0025) loads asynchronously and **retains**: a requested mesh, texture or
material stays resident until the server is destroyed. Its header said so in as many words — "out of
scope: budgets, eviction" — and its handle is a bare slot index, which is only sound *because*
nothing is ever evicted.

That is right for a level's fixed content and wrong for terrain. M19 requires streaming
(ROADMAP), and a world of heightfield tiles cannot all be resident. An outside consult
(`gpt-6-astra`, read-only, 2026-10) put it plainly: *"extend AssetServer's loading pattern with
heightfield/layer requests and releasable, generation-checked ownership; its current retaining cache
cannot provide bounded world streaming."*

**Owner decisions (Luca, recorded in the m19.8b brick spec):**

1. **Terrain streams, and collision streams regionally** — not whole-map server collision. That
   buys RAM at the price of admission/query/rollback machinery (brick 8c).
2. **M19 ends with full LOD for seamless travel** — not at bounded streaming alone (brick 8d).

Both need the same foundation: an asset server that can give memory back, and whose handles cannot
be fooled when it does. This ADR is that foundation and nothing more.

## Decision

### 1. Two ownership classes, by kind

| class | kinds | handle | lifetime |
| --- | --- | --- | --- |
| **retained** | mesh, texture, material | `AssetHandle<T>` — index | until the server is destroyed (unchanged) |
| **streamed** | heightfield, terrain layer | `StreamedAssetHandle<T>` — index + generation | until the last owner releases |

`request_heightfield(path)` / `request_terrain_layer(path)` follow the existing pattern exactly: an
immediate `Loading` handle, one job per path on the `JobSystem`, IO and decode outside the lock,
`Ready` only at `pump()` on the main thread. The one addition is that **every call takes an
ownership** of the slot — coalesced calls included — and must be balanced by one `release(handle)`.

### 2. The eviction rule

A streamed slot is in exactly one of three conditions; one mutex makes each transition atomic.

| condition | definition | handles |
| --- | --- | --- |
| **free** | not occupied; on the free list | none resolve |
| **owned** | occupied, `owners > 0` | resolve; `Loading`, `Ready` or `Failed` |
| **owed** | occupied, `owners == 0`, load job in flight | none resolve |

- The last `release` of an **idle** slot evicts it immediately: the payload is destroyed, the path
  is un-mapped, the **generation is bumped**, the index goes on the free list.
- The last `release` of a slot whose **load is in flight** only records the eviction as owed. The
  slot stays occupied — pinned — because the job will publish into it *by index*. The job evicts
  it as it finishes, under the same lock it publishes under. Nothing is freed, and no index is
  reused, under a running job. This is also why the job carries no generation of its own.
- A request for a path whose eviction is owed **adopts the in-flight load** and cancels the
  eviction, rather than reading the file twice.
- There is no "occupied, unowned, idle" condition. Both places an owner count can reach zero with
  no job in flight evict before dropping the lock.

"Evicted" means the CPU payload is freed. GPU residency is the render layer's (brick 8a), as it has
been since ADR-0025.

### 3. Stale handles

Every lookup compares the handle's generation with the slot's. A mismatch — or a slot with no owner
left — answers **not available**: `get` returns `nullptr`, `state` returns the new
`AssetState::Stale`, `release` returns `false` and changes nothing. A stale handle can therefore
neither read nor evict the index's new tenant.

`Stale` is a new enumerator rather than a reuse of `Failed`: *the file was bad* is worth a human's
attention; *you let go of this* is routine. An invalid (default) handle still reports `Failed`, as
the retained kinds do, and is not counted as stale.

### 4. Explicit `release`, not an RAII owner

The existing handle is a trivially-copyable value that lives in ECS components and crosses job
boundaries by value. An RAII owner would need a back-pointer to the server and move-only semantics,
and could no longer sit in plain component data. So ownership is an explicit count on the slot, and
the residency layer above — which already keeps one record per tile — pairs request with release.

The cost, stated: copies of one handle share one ownership. Releasing twice through two copies while
an independent owner still holds the slot spends that owner's ownership, and the count cannot tell.
An over-release with no owner left *is* caught (refused, counted as stale).

### 5. What stays retained, and why

Mesh, texture and material handles, slots, jobs and getters are **not touched**. Generalising them
would have put a generation into a handle stored across the ECS and the GPU bridge, for kinds with
no eviction policy to drive it, and no existing test covers that change. When a retained kind needs
to stream (virtual-geometry pages already have their own pool), it moves to the streamed path
deliberately.

There is **no placeholder** for the streamed kinds. A placeholder texture is a visible "missing"
tell. A placeholder heightfield would be flat ground that things stand on, collide with and
replicate. Unavailable terrain stays unavailable, so the caller defers.

### 6. Counters (CLAUDE.md guardrail 5)

`AssetServer::stream_counters()` returns a consistent snapshot; each field is moved by a test.

| counter | counts |
| --- | --- |
| `requests` | every streamed `request_*` call |
| `coalesced_requests` | …that joined an existing slot |
| `loads_started` | …that claimed a slot and submitted a job |
| `failed_loads` | jobs that could not read or validate their file |
| `evictions` | slots freed |
| `deferred_evictions` | last-owner releases that found the load in flight |
| `cancelled_evictions` | owed evictions cancelled by an adopting request |
| `stale_handle_resolutions` | `state` / `get` / `release` on a handle with no live ownership |

`live_*_slots()` and `resident_*()` report occupied slots and held payloads; an eviction lowers both.
At quiescence: `requests == coalesced_requests + loads_started`, and
`loads_started == evictions + live slots`. The churn test asserts both under contention.

They cover the streamed kinds only. The retained path is uncounted here, as before.

### 7. Threading

`request_*` and `release` are callable from the main thread or from within a job, as `request_*`
always was. `pump()` and the getters stay main-thread. No new lock and no new global: the existing
`mu_` now also guards both streamed pools and the counters, which is what totally orders a request,
a release and a finishing job. An evicted payload is moved out under the lock and destroyed after
it is dropped, so freeing a large sample vector does not stall other requests.

## The terrain streaming plan

| brick | delivers |
| --- | --- |
| **8a** | render residency: bounded GPU tile slots, generation handles, fence-safe eviction |
| **8b** | this ADR — the asset server gives memory back — plus the render integration that requests and releases through it |
| **8c** | regional collision: authoritative activation and pinning at tick barriers; unavailable terrain defers admission, never empty ground |
| **8d** | render LOD: pinned coarse coverage, crack-free transitions — the seamless-travel requirement |
| **8e** | budgets: measured byte budgets and the policy that decides what to release |

## Consequences

- A world larger than memory is now expressible at the asset layer: CPU terrain is bounded by what
  its owners hold, not by everything ever requested.
- A pointer from a streamed `get` is valid only while the caller's ownership is held. This is
  stricter than the retained kinds' "valid forever", and the header says so.
- A `Failed` streamed slot stays `Failed` (repeat requests coalesce onto it — no retry storm) until
  every owner releases; only then does a new request try the file again.
- The server honours releases; it decides nothing. Eviction *policy* is 8e's.

## Known limits

- **Not measured.** No budget, byte count or timing is claimed. The counters are slot counts.
- Generations are `u32` per slot. One index would have to be evicted 2^32 times for a handle held
  across the whole wrap to alias.
- Coalescing is by path string, as for the retained kinds: two spellings of one file are two loads.
- The deferred-eviction proof holds the job *queued*, not mid-decode. The pin is set at submission
  and cleared at publish, so both are the same condition to the code; a decode-time hook would be
  needed to observe the difference. The TSan churn test is the evidence for the running case.
- The owned-but-over-released case in §4 is undetectable by design.

## Deferred

- Reject-by-reason tallies for streamed failures (`AssetRejectCounters`): the readers support them;
  the server logs the reason and counts the failure only.
- Priorities, cancellation of a queued load, and dependent loads (a layer's material and texture).
- Moving any retained kind onto the streamed path.
