# ADR-0076 — The content root and the bundle: a game that runs with the repository out of reach

- **Status:** accepted
- **Date:** 2026-10-06
- **Decided by:** Claude (brick m20.2), within the shape [ADR-0046](0046-exported-games-and-the-blender-boundary.md) §1 fixed
- **Relates to:** [ADR-0046](0046-exported-games-and-the-blender-boundary.md) §1 (the bundle;

  `.rscene` format the entry scene uses)

> Number provisional (0076 as assigned for m20.2; main ends at 0062). Renumber at merge if needed.

## Context

M20's done criterion is that the bundle is moved off this machine with the repo out of reach,
`dedicated` runs on a box with no Vulkan, and its state digest matches the in-tree run. Before this
brick, two things stood in the way.

**Nothing resolved content relative to the executable.** The audit (grep for `RIME_SOURCE_DIR`,
`CMAKE_SOURCE_DIR`, compile-time `*_DIR` definitions, `current_path`, `getenv` and file I/O under
`engine/` and `samples/hello-game/`) found:

| dependency | where | verdict |
|---|---|---|
| `GameDefinition::entry_scene` resolved against the **working directory** | `engine/app/src/launch.cpp` (its own comment called this "the bundling brick's job") | fixed: resolved against the content root |
| entry-scene entities got **no `WorldTransform`** (`propagate_transforms` only updates entities that already have one), so PhysicsSync — which binds `RigidBody + Collider + WorldTransform` — would never simulate them | `launch.cpp` | fixed: `scene::derive_world_transforms`; unseen until now because no game had an entry scene |
| game executables carried a **RUNPATH into the Conan cache** (`~/.conan2/p/b/fmt…/p/lib:…/volk…/p/lib`) | every executable, via CMake's build RPATH | fixed for game targets: `SKIP_BUILD_RPATH` in `rime_game_content()` |
| shaders | `rime_embed_shaders`: SPIR-V compiled into the binary | **not a dependency** — no shader file is read at run time; the export fails on a loose `.spv` |
| `RIME_*_COOKED_DIR` compile-time content dirs | `samples/08`, `10`, `12`, `13`, `99-the-block`, `tests/blockkit` | **not fixed here**: not hello-game; each needs `rime_game_content()` when it is ported to a `GameDefinition` |
| `__FILE__` absolute paths in log lines | `RIME_LOG_*` | cosmetic, not a dependency (the text names a path; nothing opens it); `-ffile-prefix-map` is a follow-up |
| hello-game itself | — | read **no file at all**: its whole world was built in `setup`, so a "bundle" would have proved nothing about content |

## Decision

**1. One search, in a fixed order** (`rime/app/content_root.hpp`, `resolve_content_root`):

1. `--content <dir>` — and when given it is the **only** candidate. An operator who names a
   directory and is wrong hears so; they are not handed other content.
2. `<directory of the executable>/content`, via `platform::executable_path()` (which already had
   `/proc/self/exe`, `GetModuleFileNameW` and `_NSGetExecutablePath` backends; only Linux is run).
3. The game's in-tree content directory, **only when the executable sits in the directory the build
   wrote it to**. That is this ADR's definition of "a dev build": not a build type (Release ctest runs
   in-tree too) but "this binary has not been moved". A moved binary — a bundle — never reads the
   source tree, so a bundle with its content deleted fails even on the machine that built it.

A candidate counts only if it holds the entry scene. Failure is a refusal **before anything is
constructed**, listing every candidate with its verdict (`missing`, `exists, but has no X`,
`not considered — …`). Success prints one line naming the root and why; `RunReport::content` carries
both for an embedding caller, and `SetupContext::content_root` hands the root to the game.

**2. A game declares its content in CMake.** `rime_game_content(<target> <dir>)` defines
`RIME_GAME_CONTENT_DIR` / `RIME_GAME_BINARY_DIR` (the dev fallback's two paths, inert once the binary
moves), turns off the build RPATH, and writes an export record (`build/<preset>/export/<config>/
<target>.export`) so the export script reads where a target's binary and content are instead of
guessing.

**3. hello-game gets real content.** Its arena floor moves from `setup` into
`content/hello-game.rscene` (the entry scene, written by `hello_game --emit-content`), and `setup`
refuses if it is absent. The digests did not move: `f764d141966c92ef` at 120 ticks,
`8ba766bef103c8af` at the win, before and after.

**4. The bundle** (`scripts/export-game.sh <target> <out-dir>`): Release by default, the executable,
`content/` and a `README.txt` of the modes, written to `<out-dir>/<target>/` and refused inside the
repository. Its dependency check (readelf + ldd) requires system libraries only, no RPATH/RUNPATH, and
no link-time `libvulkan`. volk `dlopen`s the loader inside the device factory, which `dedicated`
never enters.

## Proof

`scripts/export-proof.sh` exports hello-game to `/tmp` and runs it under bubblewrap: an empty tmpfs
over `$HOME` (repository, build tree, Conan cache, `~/.rime-tools`) and over
`/usr/share/vulkan`, `/dev/null` bound over the Vulkan loader, `env -i` with `VK_ICD_FILENAMES` /
`VK_DRIVER_FILES` naming nothing. The sandbox checks that each is hidden before the game runs.
`dedicated` matches the in-tree digest at 120 ticks and at the win. `play --headless` finds no loader,
degrades to the simulation, and matches as well. Falsified three ways:

- with `content/` deleted the bundle exits 1 naming both candidates, in the sandbox and on the host;
- a one-bit-off digest is rejected;
- **mutating the moved-binary rule** (letting the fallback apply to any binary) makes the host leg
  run green on the repository's content with the right digest. The proof reports that as a failure.
  This is the failure the rule exists to prevent, and it reads as a pass anywhere the repository is
  present.

## Consequences and what is not decided

- **"Off this machine" is simulated, not done.** The repository and Vulkan are hidden on the machine
  that built the bundle. System libraries are not: the binary links `libX11`, `libwayland-client`,
  `libwayland-cursor` and `libxkbcommon` at load time, so a minimal server image needs them installed.
  Making the window system `dlopen`-only (as Vulkan already is) is the change that would make
  `dedicated` run on a bare container.
- No PowerShell twin. The Windows dependency check reads the PE import table (dumpbin), which is not
  a translation of ldd. macOS needs `otool -L`. Both are follow-ups, and the macOS/Windows
  executable-path backends are untested here.
- The bundle has no manifest yet. ADR-0046's `rime-game.toml`, content hash, `LICENSES/` and
  `rime package` remain M20 work, along with network input for `dedicated`, the listening modes and
  the no-argument launcher.
