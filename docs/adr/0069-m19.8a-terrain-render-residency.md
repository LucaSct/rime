# ADR-0069 (m19.8a): Terrain render residency — the world manifest, fence-safe slots, the builder

- Status: Accepted
- Date: 2026-10-06
- Number: 0068 is ADR-0068 (m19.8c, regional collision) on its own branch; renumber at merge if
  the two clash.

## Context

m19.3–m19.7 drew terrain whose every tile was uploaded once and kept until `TerrainPass` died
(ADR-0062: "no streaming"). M19 needs streaming (ROADMAP), and m19.8b (ADR-0067) gave the
`AssetServer` the CPU half: heightfields and terrain layers are owned, released and evicted with
generation-checked handles. ADR-0067's plan names this brick **8a**: bounded GPU tile slots,
generation handles, fence-safe eviction. Two more pieces were also waiting on it:

- **no map of the world.** Nothing said "tile (3, −2) is this file", so nothing could choose tiles
  by distance without opening every file;
- **no engine-side builder.** ADR-0066 §2 decided that a palette slot is dispatched on the referenced
  asset's kind, and its addenda deferred the code: "the tests build palettes directly".

An outside consult (`gpt-6-astra`, read-only, 2026-10) proposed the shape adopted here: a manifest of
grid coordinates with shared spacing/quantisation and matching borders; a bounded RAM→GPU tile
replacement with synchronous uploads and generation handles; M18.5's confirmed-upload and
last-reader-retirement **rules**, not its geometry ABI; missing visuals allowed and counted.

**Owner decisions (Luca, in the m19.8a spec):** collision streams regionally in its own brick (8c —
not touched here); M19 ends with full LOD for seamless travel (8d, later). This brick is bounded GPU
residency plus the builder.

## Decision

### 1. The terrain world manifest (`rime::assets::TerrainWorld`)

A small data type in `rime_assets` (world data, not render data: brick 8c reads the same map) plus a
tab-separated file in the asset `Manifest`'s house style:

    grid  <samples> <cell_x> <cell_z> <height_scale> <height_offset> <origin_x> <origin_y> <origin_z>
    tile  <x> <z> <revision> <min_y> <max_y> <asset-id-hex> <path>

The grid is declared **once**. Two tiles meet without a crack exactly when they share spacing (edge
vertices land on the same XZ), share quantisation (equal integers are equal heights) and carry the
same integers along the shared edge. So:

- `check_tile(grid, coord, asset)` refuses a size, spacing or quantisation mismatch — spacing and
  quantisation **bit for bit** — and a placement off its grid cell by more than 1 mm;
- `edges_match` compares the shared border **integers** of two edge neighbours;
- a duplicate coordinate is refused at parse/add time, first tile kept;
- every refusal is counted by cause (`TerrainWorldRefusals`); a malformed line refuses the whole
  file, as `Manifest` does.

`Manifest::parse` learns the `heightfield` and `terrain_layer` kind names so a palette id resolves
to its cooked file.

### 2. `TerrainResidency` (`rime::render`, new files beside `TerrainPass`)

Placed in `rime_render` because it owns GPU resources through `TerrainPass` and depends only on
interfaces render already uses (`AssetServer`, the RHI). Nothing else in `rime_render` includes it;
deleting its files and CMake lines leaves the engine building, the guardrail `TerrainPass` keeps.

- **A fixed budget of tile slots** (constructor argument). Each frame `begin_frame(eye)` wants the
  tiles whose footprint is within `activation_radius`, keeps resident ones within
  `retention_radius` (≥ activation — the hysteresis that stops boundary thrash), requests wanted
  heightfields through `AssetServer::request_heightfield`, uploads ready ones into free slots
  **nearest first**, and hands each CPU heightfield back (`release`) as soon as it is on the GPU.
- **Eviction is on demand**: a resident tile beyond retention is only a candidate, evicted
  farthest-first when a wanted tile needs its slot. A kept tile is never evicted for a wanted one;
  the wanted one waits, counted as `no_free_slot`.
- `TerrainPass` gains `release(id)` (ids recycled) and `tile_bytes(id)`, so the pass's own store is
  bounded by the slot count, not by the number of tiles ever seen.

### 3. Fence-safe eviction: M18.5's rules

`TerrainSlotTable` is the policy with no GPU in it (M18.5's cache/pool split), so the rule can be
driven with fake frames:

    Free ──acquire──▶ Occupied ──evict (generation++)──▶ Retiring ──reclaim(watermark)──▶ Free

- every draw records "frame F read slot s";
- submitted frames' `SubmitTicket`s are kept **in order**; the watermark is the newest frame with it
  and every predecessor complete (`Device::is_complete`) — `VirtualGeometryPagePool::begin_frame`'s
  walk;
- **evict** bumps the generation at once (no new draw can name the slot) and parks it Retiring;
  **reclaim** — destroying its GPU resources and freeing it — happens only when the watermark has
  reached the last frame that read it;
- `end_frame_blocking` is the one case where "submitted" is "retired"; an invalid ticket never ran
  and retires at once; a frame never ended is waited idle at the next `begin_frame`, counted.

### 4. Generation-checked ids

`TerrainResidentId` = slot + generation. `add_tile` with a stale id declares **no pass** (the frame
is byte-identical to one without the call) and counts `stale_draws`; the generation check and the
read record are one call (`mark_read`), so a draw can never be recorded against a tenant it did not
name.

### 5. The builder (`TerrainLayerBuilder`): kind dispatch and shared textures

A palette slot's `AssetId` resolves through the asset manifest, and the builder dispatches on that
entry's **kind**:

| kind | yields |
| --- | --- |
| `Material` | base colour, metallic, roughness; no texture, `uv_scale` 1, contrast 0 — today's path |
| `TerrainLayer` | its material's scalars + its `albedo_height` texture + `uv_scale` + `height_contrast` |
| anything else / unlisted | refused, counted (`wrong_kind` / `unresolved_ids`); the palette fails |

The kind is read from the manifest entry, which `rime cook` writes from the same header ADR-0066 §2
says to read — no IO on the frame thread. The typed request re-reads the header, so a manifest that
lies about a kind fails the load (`WrongKind`) and is counted rather than mis-decoded.

Layer textures are uploaded **once** (RGBA8_SRGB only — ADR-0066 §3; anything else refused and
counted) and reference-counted per palette slot. `release` returns exactly the references its slots
took, and destroys a texture with its last reference. The residency releases a palette at slot
**reclaim**, so a shared texture outlives every frame that sampled it. The streamed layer record is
released as soon as its four fields are copied.

### 6. Missing visuals are allowed and counted

No coarse cover yet (8d). Every frame, every wanted tile not resident is counted under exactly one
reason: `not_loaded` (heightfield or palette loading), `no_free_slot`, `upload_failed`, `refused`
(load failed, palette failed, or `check_tile` / `edges_match` said no — by cause in
`refusals()`). A refused or failed tile is sticky while kept and forgotten when it leaves retention.

## Proofs (`tests/terrain_render/terrain_residency_test.cpp`, `tests/assets/terrain_world_test.cpp`)

Worlds are real cooked files written by test-side encoders that are first round-tripped through the
engine's readers. Measured on the RTX 3060 (default) and RADV:

- **(a) plateau** — 333-frame traversal of a 4×4 world, 4 slots: occupied slots ≤ 4 and tile bytes
  ≤ 4 × 7448 every frame; 26 uploads, 22 evictions, 22 reclaims; uploads = evictions + resident.
- **(b) fence safety** — fake frames: a slot read by frame 7 is Retiring at watermark 6, reused at
  7. GPU smoke on `device.submit` with three frames in flight: the test's own tickets show no
  recycled slot's last reader unretired; RADV measured 16 reclaim waits on an unretired reader, the
  RTX 0 (its frames retire before the next `begin_frame`).
- **(c) stale id** — memcmp-identical to drawing nothing, counted; hysteresis holds a kept tile.
- **(d) builder** — a TerrainLayer palette renders bit-identically to the hand-built one (texture via
  `GpuAssetBridge`); a Material palette matches the scalar path; a shared texture is uploaded once
  and destroyed exactly once with its last palette, directly and through the residency.
- **(e) seam** — two resident neighbours cover all 64×64 pixels across the seam.
- **(f) refusals** — duplicate coordinate, spacing, border, oversize upload: each counted.

Falsified, each restored: reclaim without the watermark → (b)'s fake-fence case red (5 assertions);
the GPU smoke stayed green, because its independent check runs after `begin_frame`'s synchronous
uploads have drained the queue (and the validation layer reported nothing). Generation ignored in
`resolve` → (c) red, memcmp included (6 assertions). A leaked texture reference → (d) red
(10 assertions).

## Consequences

- A terrain larger than GPU memory is drawable, with tile memory bounded by a slot count.
- `TerrainPass` ids are now recycled after `release`; holders of a released id must not draw it.
  `TerrainResidency` is the safe way to hold them.
- A hole is visible where a wanted tile is missing, and the counters say why.

## Known limits

- **Holes, not coarse cover** (8d). The budget is a slot count, not bytes (8e); bytes are measured.
- **Border refusal is order-dependent**: the second of two mismatched tiles to arrive is refused. A
  mismatched world is a cook bug; the counter is how it is found.
- **Synchronous uploads** on the frame thread (`write_texture` stalls); fine at these sizes,
  unmeasured at real tile sizes.
- **Retained CPU textures and materials**: layer textures leave the GPU with their last palette but
  stay decoded in the AssetServer (ADR-0067 §5).
- **The cooker does not yet write** `heightfield` / `terrain_layer` manifest lines; the tests write
  their own manifest. Nor does any tool write a terrain world file.
- The GPU fence smoke cannot fail deterministically (see Proofs); the fake-fence case is the proof.
- `min_y` / `max_y` and `revision` are parsed and carried, not used (culling; 8c).

## What m19.8d adds

Pinned coarse coverage so a wanted-but-missing tile draws coarse ground instead of a hole, render
LOD per tile, and crack-free transitions between LODs — the seamless-travel requirement. The slot
table, generation ids and fence rule here are what its LOD levels will be held in.
