# ADR-0061 (m19.2): Convex queries against terrain — per-triangle kernels, and the one rule that is not EPA's

- Status: Accepted
- Date: 2026-10-04

## Context

[ADR-0060](0060-m19.1-heightfield.md) landed the cooked heightfield, its checked reader, the grid-walk
raycast and the contact build — and deferred, by name, the three places a **convex** shape meets
terrain:

| site | M19.1 behaviour |
| --- | --- |
| `PhysicsWorld::shape_cast` | skipped the body, bumped `heightfield_query_skips()` |
| `PhysicsWorld::penetration` | skipped the body, bumped `heightfield_query_skips()` |
| speculative CCD in the contact build | emitted nothing, bumped `heightfield_ccd_skipped` |

ADR-0060 called the first two "the next physics brick for M19", because a character controller on
terrain needs a per-triangle cast, and the third is why a fast projectile could pass clean through
the ground. All three were *counted* rather than silent, which is the only reason this brick could
be scoped from measurement instead of guesswork.

## Decision

### 1. Per-triangle kernels, not a support function for the field

A heightfield is not convex, so it has no support function — `support_local` returns the origin for
it and says so. A cell's two **triangles** are each convex, and the engine's existing GJK, EPA and
conservative-advancement cast already handle any convex pair through a support function. A
three-vertex `narrowphase_detail::PolyView` with its `PolySupport` *is* a triangle's support
function.

So terrain needs **no new geometric kernel** — only an enumeration of candidate triangles and a rule
for reducing the per-triangle answers. Rejected: picking one "locally convex" piece and running the
kernels against it, which is what engines advertising "heightfield support in GJK" generally do. It
gives wrong answers near a ridge, where the nearest triangle is not the one the shape is about to
hit.

### 2. The candidate set is the shape's bound over the grid, from one shared definition

`cell_range` was promoted out of the contact build's local lambda so the queries and the narrowphase
share **one** definition of "which cells does this bound touch". Two copies would be two chances to
disagree about a bound landing exactly on a grid line, and a query that enumerated a different set
from the narrowphase would report hits the solver never resolves. For a cast or a speculative
contact the bound is the **swept** one — conservative, because each coordinate of a linearly swept
convex shape is linear in `t`, so the shape stays inside the union of its endpoint boxes.

### 3. The budget is explicit and counted, and reuses M19.1's counter

A 500 m cast over a 0.37 m grid sweeps ~1.8 M triangles. Enumeration therefore stops at
`kMaxQueryTriangles` (8192 triangles = a 64×64 cell patch) and reports that it was truncated; the
caller bumps the same `heightfield_query_skips()` counter, which keeps meaning **"the query could
not look at all of it"** rather than "the query found nothing". A character-scale sweep touches tens
of triangles, nowhere near the cap.

**What was found is still reported on a truncated look.** A real hit does not become less true
because the search was incomplete, and suppressing it would turn a conservative answer into a wrong
one.

### 4. Depenetration does NOT run EPA per triangle — and this is the brick's real subtlety

EPA answers *"what is the shortest translation separating these two convex shapes"*. A cell triangle
is a **zero-thickness surface**, so for a shape that has sunk into the ground the shortest separation
is very often **deeper into it**.

Measured while building this brick: a sphere of radius 0.5 whose centre sits 0.1 below a flat tile
spans `[-0.4, +0.6]` about the surface, and EPA **correctly** reported that pushing it **0.4 down**
separates it from the triangle sooner than pushing it 0.6 up. That is the right answer about a
triangle and a catastrophic answer about ground: a character controller acting on it would
depenetrate itself into the rock. The sideways case is the same bug — a shape over a shared edge can
leave a triangle's extent more cheaply than it can leave the surface.

The contact build already owns the correct rule, because the narrowphase had to solve exactly this:
`sphere_vs_triangle` and friends accept a below-plane overlap **only** when the shape lies over the
triangle's interior, and then resolve along the triangle's own normal — *"straight back up, never
sideways"*. So `penetration` against terrain **reuses `heightfield_contacts_local`** and takes its
deepest contact. One definition of "inside the ground", shared by the solver and by the query that
tells a caller how to get out of it.

Reductions: **deepest** wins for penetration (repeatedly resolving the worst violation strictly
reduces the maximum, so a shape wedged in a crevice converges out), **earliest** for the cast,
**nearest gap** for the speculative contact (a farther triangle winning would let the solver permit
motion through the nearer one). Every one tie-breaks on the lower triangle id, so no answer depends
on enumeration order for any reason other than the grid.

### 5. Speculative CCD reuses M7.10's rule rather than inventing a terrain one

`collide_speculative`'s comment claimed the path was *"shape-agnostic by construction"*. It was not
quite: it was written over two `ShapeDesc`s, and a terrain triangle has a support function but no
`ShapeDesc`. The rule now lives in `collide_speculative_supports`, over two support callables, and
the `ShapeDesc` overload is that function with `ShapeSupport`s built for it — so the convex path's
behaviour is unchanged **by construction** rather than by re-derivation, and a body approaching
terrain is arrested by exactly the same closing-speed condition and slop that arrests it against a
wall.

The terrain routine returns its normal in `patch_to_manifold`'s **terrain → shape** convention, not
the `a → b` convention `collide_speculative_supports` hands back, so the caller applies one
identical "flip if the terrain is body b" rule to both the exact and the speculative path. **It was
backwards in the first version of this brick**, and the fast-projectile test measured the body
sailing through the ground exactly as it had before CCD was wired at all — recorded because the
symptom of a sign error here is indistinguishable from the feature not existing.

## Consequences

- `shape_cast`, `penetration` and speculative CCD all work against terrain. `heightfield_query_skips`
  and `heightfield_ccd_skipped` now count **only** a budget-truncated look, which is a narrower and
  more useful meaning than M19.1's.
- A fast projectile no longer tunnels: a 1 cm sphere at 300 m/s (5 m per 1/60 s step, hundreds of
  times its own thickness) is arrested at the surface, where the control run with CCD off ends 24 m
  below it.
- **Known limitation, with a gate on it.** A shape sunk below the surface whose centre lies exactly
  on a grid **vertex** or on a cell **diagonal** gets **no** depenetration answer: the below-plane
  branch requires the centre to project into a triangle's interior, and on those lines no triangle's
  interior contains it. It is inherited from ADR-0060's contact rule, not introduced here, and it
  affects **depenetration only** — a body resting *on* terrain uses the above-plane path, which does
  accept edge and vertex features, and the watertightness proof covers exactly those points.
  `heightfield: a shape sunk exactly on a vertex or diagonal gets NO depenetration` pins it, so a
  later fix turns that test red rather than passing unnoticed. The fix belongs to the contact rule
  (accepting a boundary feature without double-counting it across the triangles that share it, which
  is what `push_unique`'s dedup exists for), so it is left to the brick that owns the controller.
- **Deferred:** the banded enumeration that would retire the budget rather than raise it — walking
  the sweep with the grid DDA and testing only the cells within the caster's radius of each step,
  which is O(cells crossed) instead of O(cells in the bound). Also still deferred from ADR-0060:
  per-cell best-fit diagonals, terrain holes, heightfield bodies through the ECS `Collider`, and a
  per-cell min/max hierarchy for long rays.
- `penetration_vs_heightfield_local` keeps a `truncated` out-parameter it never sets, so all three
  terrain queries present one signature to the caller and a later banded enumeration can set it
  without a signature change.
