# ADR-0109: m20.9 — several clients predict one contended object

- Status: Accepted (owner, 2026-10-26: "build contention next, on codex"). Design: astra consults
  `c-contention.out` and `d-adr0109-review.out` (gpt-6-astra, verified by the orchestrator); draft
  `adr-0109-draft.md` superseded by this text.
- Extends: ADR-0106 (one bounded interaction group), ADR-0108 (seats). Depends on: the hello-game collision brick
  (server keeps players outside the crate and apart, shared `integrate_player`), m20.8c (lifecycle fixes, N-client proof).

## Context
With several seats the crate is only mirrored (`network_input.cpp` disables per-seat policies in multi-seat), so a
pushing client sees its own ball now and the crate ~100 ms in the past. Unity NetCode predicts remote players from
serialized commands and runs predicted physics in rollback; Rocket League predicts the ball and cars under full server
authority (Cone, GDC 2018). Neither is inherited here; they support the direction.

## Decision
1. **Every member seat predicts; the server is the only authority.** Per-seat membership policies are created and
   reset per occupant in multi-seat. "Touching" keeps meaning ANY player touches the crate: nobody leaves the group
   of a crate that is being pushed.
2. **Context lives in the crate's entity payload (crate payload v2; `InteractionProfile::version` bumped).** Exact
   little-endian layout: `u8 version=2, u8 proxy_count, u16 reserved=0, u16 owner_seat, u16 owner_generation,
   u32 context_revision`, then the existing 52-byte crate state, then `proxy_count` 48-byte records
   `u16 seat, u16 seat_generation, u32 net_index, u32 net_generation, f32 position[3], f32 velocity[3],
   f32 axes[2], u32 held` (no press edges). Maximum 208 bytes, under the 512-byte entity limit; the owner's 20-byte
   group state is untouched. Validation: exact length, finite values, valid quaternion, unique identities, owner
   excluded, canonical (ascending seat) order. Message budget: complete checkpoint parts are budgeted BEFORE spawn
   outcomes; outcomes defer oldest-first into what remains.
3. **The server captures what each seat EXECUTED this tick** (the scheduled command, including synthesized and
   neutral stand-ins), not the last packet. Capture hooks gain the recipient's identity and a span of
   seat/entity/NetId/executed-command records; client construction gains the owner identity.
4. **Restore becomes transactional.** A prepare step validates every member's typed payload and builds the replacement
   prediction world from the complete checkpoint BEFORE any roster/state/spawn mutation; a commit step installs it
   after entity restores. A refused checkpoint leaves simulation, history, roster and ledger unchanged.
5. **Coupled replay.** The prediction world holds floor, ALL players (own + proxies) in ascending seat order, then
   the crate; sleeping off. Each replay tick: move players in seat order with `integrate_player` (earlier players'
   updated poses, later players' previous poses, the pre-step crate), drive every kinematic body directly, step
   physics once. Proxies repeat their checkpointed executed command (axes, held; no edges). Owner movement is split
   from the existing spawn simulation hook so nothing integrates twice. Proxy trajectories are recorded during the
   coupled replay. At seed age 64 ticks a client stops extrapolating and waits for a fresh checkpoint.
6. **Identity.** Proxies are private context, outside the authoritative entity roster: `context_revision` advances
   when proxy identities change; the membership epoch still advances for crate/player/spawn roster changes. Seat
   generation + NetId generation prevent reuse aliasing; identities are frozen during a replay.
7. **Scope cap.** At most FOUR seated players use contention prediction (all other players captured); above that the
   crate falls back to mirrored for everyone, counted `interaction_contention_unsupported`.
8. **Presentation.** Proxy `RenderTransform`s are overridden by generational NetId through the smoother, with smoothed
   entry and return to the mirror; destroyed identities are forgotten. Independent smoothing does not preserve
   visible contact exactly — accepted and measured.
9. **Proof.** No universal correction bound is claimed from input error (a reversing remote player is off by up to
   2·v·H·dt = 8.53 m). A crate bound `B ≤ 2·Vc·H·dt` is claimed only with a separately verified crate
   displacement-speed envelope `Vc`. Smoother: `E_next ≤ exp(−Δt/τ)·E + correction`, snaps counted. Gates: digests
   equal; local influence on the crate within 1 tick (opposing pushes may legitimately net zero motion); a scripted
   remote reversal must distinguish correct proxies from the disabled-proxy and stale-seeded controls; a
   fresh-predictor oracle matches the live replay every tick through a substitution and a seat reuse; malformed
   final proxy record → state unchanged; proxy→mirror transition continuous.

## Bricks (each with its cheapest gate)
- m20.9a codec + transactional restore — a malformed final proxy record leaves all state unchanged.
- m20.9b capture + coupled replay — fresh-predictor equality every replay tick through a substitution and a seat reuse.
- m20.9c presentation + the process proof — proxy→mirror continuity; the scripted reversal separates correct proxies
  from the controls.

## Consequences
- Opposing pushes correct whenever a remote player reverses; unknown remote input stays a guess.
- Two opposing kinematic capsules can squeeze the crate; server physics there is measured before corrections are
  blamed on networking.
