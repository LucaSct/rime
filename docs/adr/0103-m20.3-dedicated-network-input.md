# ADR-0103: m20.3 — network input for `dedicated`, and the listening contract

- Status: Accepted (owner, 2026-10-24)
- Date: 2026-10-24
- Extends: ADR-0046 §1 (the launch modes), ADR-0056 (m20.1 `run_game`), ADR-0076 (m20.2 bundle)

## Context

`run_game` makes `play` and `dedicated` real (ADR-0056); `dedicated` runs the game's fixed-tick
simulation with no device, but its input is the autopilot or nothing. A dedicated server nobody can
drive is a benchmark, not a server, and it is the next item on ADR-0076's "not yet" list.

Almost everything the input path needs already exists and is proven (M11/M12): real non-blocking
IPv4 UDP (`platform::UdpSocket`, `net::UdpLink`), `net::NetDriver` sessions with reliable-ordered and
unreliable-sequenced channels, identity checks and incarnation salts, and `ClientInputSender` /
`ServerInputReceiver` with redundant, deduplicated `InputCommand` delivery. What is missing is the
wiring into `run_game` — and one semantic gap that two independent reviews found on their own:
`ServerInputReceiver::drain` (`engine/replication/src/input.cpp:393`) reports what was *taken out of
the buffer*, which is not proof the simulation *ran* it. Guardrail 5 says a per-peer "what they have"
fact may only strengthen on confirmed holding; for input, holding means **executed into authoritative
state**, and an acknowledgement built on "arrived" or "drained" is the proxy the guardrail forbids.

The owner asked for the design to follow modern, well-researched netcode rather than be invented
here, and commissioned two independent web-search consults (gpt-6-astra via codex, and Opus 5.5)
with the same brief. Both are kept with the brick's evidence
(`reports/rime-oct24-netcode-research/`). They agreed on every structural point below; where they
differed, the choice made and why is stated inline.

## Decision

### 1. Keep `InputCommand`; wrap it in a versioned envelope (InputV2)

Rime keeps its own codec rather than adopting another engine's wire format, and borrows the
*mechanisms* the published designs share — redundant recent commands per packet (Unity Netcode for
Entities' command stream; Overwatch, GDC 2017), a server-side jitter buffer with an execution
deadline (Riot, "Peeking into VALORANT's netcode", 2020), and acknowledgement against what the server
actually holds (Fiedler, "Snapshot Compression", 2015).

- **Handshake** (on the reliable channel, once per session): the client offers `codec_min..codec_max`
  plus a `schema_hash` naming the game's input profile; the server selects the highest common codec
  or refuses with a reason (`version`, `schema`, `full`). Only codec 2 exists.
- **InputV2 packet** (unreliable-sequenced): `tag:u8 codec:u8 count:u8 reserved:u8`, then `count`
  commands oldest-first, each `sequence:u32 move_x,move_y,yaw,pitch:f32 held,pressed:u32` — 28 bytes,
  absolute values, no delta coding. **Redundancy: the newest command plus two predecessors** (88
  bytes). *Astra proposed this; Opus proposed delta-coded copies over a 32-command window and itself
  doubted the delta coding was worth it at this size. At 28 bytes a command, plain redundancy wins on
  simplicity; adaptive redundancy (up to 8) is a later brick that needs loss traces first.*
- **Validation before mutation:** a packet is accepted whole or not at all — wrong length, a count
  outside 1..16, a non-finite float, an unknown codec or a non-zero reserved byte refuses it, and
  every refusal is counted by reason.

### 2. The server executes from a bounded, sequence-indexed buffer

One command is executed per player per simulation tick. Late (already-retired) and far-future
(beyond the ring) commands are refused and counted; a duplicate is counted and ignored. When the
next command has not arrived by its deadline the server **synthesizes** one — held/axis state
repeated, `pressed` edges cleared, neutral after 100 ms of silence — and that tick is recorded as
*synthesized*, never as applied. The buffer starts at a fixed one tick of slack; adapting it to
measured jitter (both consults: target ≈ 1 + p95 jitter, clamped 1–4, client steers its lead) is a
later brick, because its constants need Rime's own traces.

### 3. The acknowledgement is EXECUTION, not arrival (InputResult)

After each simulation commit the server publishes `server_tick:u64 retired_through:u32
applied_mask:128 bits`. **Retired** means "will never execute later"; a mask bit means "this exact
command ran". A synthesized tick sets no bit. The client prunes its redundancy window and its
reconciliation history only on `retired_through`/`applied_mask` — never on send success, never on
receipt. *This is astra's shape; Opus's `consumed_through` + synthesized-mask is equivalent in
spirit, but "retired" plus "applied" says the guardrail's distinction in the field names
themselves.*

### 4. Transport: UDP now, with the browser door left open for free

Plain UDP through the existing session layer. Application messages never see a socket address;
payloads stay ≤ 1200 bytes (the QUIC datagram floor, and netcode.io's maximum), so the same messages
can later ride QUIC DATAGRAM (RFC 9221) / WebTransport through a gateway that feeds the same session
layer. No QUIC in the engine now.

### 5. The listening contract

```
mygame dedicated [--listen ADDR:PORT | --port N] [--offline] ...
mygame play --connect HOST[:PORT] ...
```

- **A dedicated server listens by default**, on `0.0.0.0:7463`, because a server that does not listen
  is not one (srcds, Minecraft and Factorio all do). `--offline` keeps today's behaviour — the
  existing `--dedicated-proof` and bundle export proof pass it. *7463 spells RIME on a phone keypad,
  has no IANA assignment (checked 2026-10-24 against the service-name registry), and sits below
  Linux's ephemeral range. Astra proposed 7777, which IANA assigns and Unreal and Terraria servers
  use.*
- `--listen ADDR:PORT` is canonical (Factorio's `--bind` is the precedent); `--port N` is shorthand
  for `--listen 0.0.0.0:N`. Both together, or either with `--offline`, is a usage error.
- **Port 0** is allowed and means "the OS picks"; the real bound port is read back from the socket
  and reported. Tests always use it. A bind failure **never** falls back to another port, and UDP is
  never bound with `SO_REUSEADDR`.
- **IPv4 only in this brick**: bracketed IPv6 syntax (`[::]:7463`) is accepted by the parser and
  refused with a clear "IPv6 is not supported yet" — so the grammar never has to change.
- **stdout carries only machine-readable events, one JSON object per line; logs go to stderr.** The
  first is `{"event":"ready","transport":"udp","bind":"0.0.0.0:7463","codec":2,"auth":"none"}`,
  flushed after the socket is bound and the simulation is initialised, and never printed on failure;
  later ones (`client_connected`, `client_left`, `bind_failed`) extend the same stream. *Opus's
  JSON-lines shape over astra's `RIME_READY {json}` prefix: one format, no second grammar.* stderr
  also prints a human warning that the server is unauthenticated and which interfaces it is reachable
  on.
- **Exit codes stay the shipped ones** (`launch.hpp`: 0 ok, 1 failed, 2 usage, 3 not yet): a bind
  failure is 1, with its errno named in the `bind_failed` event. *Opus proposed `sysexits.h`
  numbers; consistency with a contract already shipped in m20.1 wins.*

### 6. LAN, unauthenticated — and what that obliges

The owner chose LAN exposure without authentication for this brick. Incarnation salts stop stale
sessions; they are **not** authentication. So the listener must bound the work an anonymous peer can
cause: a connection request is never answered with more bytes than it carried (no amplification), one
client is admitted in this brick and a second is refused with a counted reason, pending handshakes
are capped and time out, and every refusal path has a counter. The planned upgrade is netcode.io-style
connect tokens (authenticated encryption, replay protection), named here so the wire leaves room for
it: the envelope's reserved byte stays zero until then.

### 7. The proof (the brick's done-criterion)

A GPU-free CTest launches `hello_game dedicated --listen 127.0.0.1:0` and a separate headless client
process that reads the ready event, connects, and sends a bounded scripted input sequence. Proof-only
telemetry returns every command the server **actually applied** (per tick) and its final state
digest. The client replays that applied trace through the same game simulation and requires an equal,
non-zero digest that differs from a zero-input control's; it also requires zero device and
presentation calls and no `libvulkan` mapped in the server (the m20.1 checks). Negative cases are
separate gates: malformed, truncated, oversized and non-finite packets; a wrong codec and a wrong
schema hash; a second client; a stale incarnation; a bind conflict (exit 1, no ready event); the
usage errors above; and a client that goes silent (synthesized ticks counted, input neutralised).

## Consequences

- `dedicated` becomes a real server on the LAN; `host`, `browser` and `stream` still refuse (exit 3).
- Every existing `dedicated` invocation that should stay offline has to say `--offline`. That is a
  behaviour change, made deliberately, in the same brick as the proofs that pass it.
- Not in this brick: multiplayer snapshot convergence, adaptive buffering and redundancy, IPv6,
  authentication, `--connect` for `play` (the proof's client is a test process).
- Cross-platform determinism is still not established for destruction replay (CLAUDE.md records
  macOS and Linux flipping the same gate), so a remote-play brick that replicates destruction needs a
  hash-mismatch counter and checkpoint repair before it claims convergence across builds.
