# City frame cost: bounded source diagnosis

**Measured (parent's native capture).** On NVIDIA 3060/615.78 at 1280×720, real mailbox, 1,981 frames per capture and 600 frames per hip/ADS/turn phase, repeated city/control/control/city: hip p50 was 9.197/9.980 ms city versus 3.542/3.557 ms control. ADS p50 was 18.690/18.971 versus 6.663/6.530 ms; p99 was 22.290/23.497 versus 8.919/8.954 ms. ADS median CPU zones were sim 2.15, declare 2.0, execute 14.4 ms city versus sim 0 (many frames had no tick), declare 1.14, execute 5.0 ms control. Acquire 0.02 and present 0.09 ms do not explain the gap. The city has 32 buildings/4,800 support nodes versus 8 buildings originally; support nodes are **not established as render draw count** by these measurements.

**Source-grounded diagnosis.** `frame.execute` wraps `RenderGraph::execute` before submit/present ([application.cpp:334-345](../../../engine/app/src/application.cpp#L334)); `execute` compiles the graph, assigns resources, opens each pass and calls its recording callback ([render_graph.cpp:627-739](../../../engine/render/src/render_graph.cpp#L627)). It is a CPU zone, **not GPU duration**. The large ADS execute delta is consistent with more command recording, but CPU/GPU attribution remains unmeasured. Graph GPU timestamp pairs exist per pass ([render_graph.cpp:635-645](../../../engine/render/src/render_graph.cpp#L635)).

Every render call extracts all mesh-bearing entities ([scene_renderer.cpp:100-115](../../../engine/render/src/scene_renderer.cpp#L100)); part leaves are one mesh entity per part ([part_leaves.cpp:173-184](../../../engine/destruction_render/src/part_leaves.cpp#L173)). Camera culling partitions the list, retaining hidden draws ([scene_renderer.cpp:487-545](../../../engine/render/src/scene_renderer.cpp#L487)). The camera depth/velocity/forward passes get only the visible prefix, but shadow passes get **all** draws ([scene_renderer.cpp:819-868](../../../engine/render/src/scene_renderer.cpp#L819), [scene_renderer.cpp:912-950](../../../engine/render/src/scene_renderer.cpp#L912)). Each cascade records that full list ([shadows.cpp:170-188](../../../engine/render/src/lighting/shadows.cpp#L170)); each invalidated local shadow slot does too ([local_shadows.cpp:185-211](../../../engine/render/src/lighting/local_shadows.cpp#L185)). Each depth pass repeatedly scans draw partitions; actual draws bind buffers and issue indexed calls ([passes.cpp:83-129](../../../engine/render/src/passes.cpp#L83), [passes.cpp:227-261](../../../engine/render/src/passes.cpp#L227)). Thus off-camera city geometry **can** scale shadow recording and GPU work; actual caster relevance is unknown.

Visible ADS declares a 512×512 second `SceneRenderer::render` on the same world, with the same lighting; hip/closed pupil does not ([main.cpp:2301-2335](../../../samples/99-the-block/main.cpp#L2301)). Both views therefore repeat extraction, uniform setup, and potentially shadow passes. The ADS increment is plausible, but the measured zones do not apportion it.

**Narrow next step.** On the same native A/B route, record per-view (main/optic) extracted, camera-visible, and shadow-submitted draw counts; cascade count and spot slots rendered/reused; CPU `compile+assign` and per-pass recording times inside `RenderGraph::execute`; and existing per-pass GPU timestamps, including overflow status. One focused control is a paired, unchanged-camera frame with optic feed hidden versus visible, preserving lighting and city geometry, to quantify the second view. If shadow recording dominates, test a conservative light-frustum caster filter per cascade/spot against `culling_test`, `gi_thesis_test`, and optical/spot sensitivity proofs before adopting it. Camera-frustum removal is contradicted by the documented off-screen-occluder regression ([scene_renderer.cpp:500-515](../../../engine/render/src/scene_renderer.cpp#L500)). No redundant work is established as safely removable from this evidence alone; feature disabling or weaker gates would not diagnose the cost.
