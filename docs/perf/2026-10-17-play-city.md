# Native city play: measured cost blocks landing

**Keep the city PR open.** In two repeated native captures, the 32-building city's
ADS frame-loop median was **18.690 / 18.971 ms**, versus **6.663 / 6.530 ms** for
the eight-building control. Both city ADS medians exceed the 16.6 ms frame target.
These are observations, not an eligible baseline or a formal regression-gate pass:
the city captures' GPU clocks did not satisfy the existing 2% stability bound.

## What was measured

RTX 3060, NVIDIA 615.78.08, Ryzen 9950X3D, performance CPU governor, Linux
7.2.10-1-cachyos, Hyprland 0.56.2. The project `release` preset is
**RelWithDebInfo**, sanitizer off. A real Wayland window presented in mailbox mode
at **1280×720**, on a 1920×1080 / 60 Hz display. Extents stayed constant throughout
all four captures. These are render-loop intervals, **not displayed FPS**.

The harness copies the production `run_play` source and drives the existing native
application loop, with deterministic phase selection, fixed hip/ADS orientation,
and an elapsed-time-based turning sweep. It records 1,981 frames: 60 warmup, 600
hip, 60 aim settling, 600 ADS, 60 turn settling, 600 turning, and a final frame.
Intervals are joined to the preceding render and that render's CPU zones.

Order: **city, control, control, city**. Local CI build/test processes were absent
at each capture's start and end; the waiter also required a quiet interval before
launching. An earlier 451-frame city smoke overlapped CI and is excluded here.
The capture runner did not implement the standard script's continuous foreign-CPU
watcher, so this is not a certification that every other process stayed idle.

The control disables the whole generated city assignment in the copied source.
It retains the environment, streamed terrain, weapon/viewmodel, structural-support
helper, lighting, and presentation path. It therefore compares the city brick as
a whole: added buildings, new lamp/barrier geometry, and enlarged ground. It does
not isolate the cost of the 24 buildings alone. Turning follows elapsed time, so
its exact camera sequence differs with frame cadence; hip/ADS orientations match.

## Repeated observations

Each table entry is p50 / p99 in milliseconds, over 600 intervals.

| View | Eight-building control 1 | Control 2 | 32-building city 1 | City 2 |
|---|---:|---:|---:|---:|
| Hip | 3.542 / 5.323 | 3.557 / 4.997 | 9.197 / 12.584 | 9.980 / 12.602 |
| ADS | 6.663 / 8.919 | 6.530 / 8.954 | 18.690 / 22.290 | 18.971 / 23.497 |
| Turning | 3.094 / 4.442 | 3.282 / 4.541 | 7.472 / 11.835 | 7.781 / 11.944 |

All captures recorded **zero shots, no charge, and 304 resident terrain tiles**.
Every measured ADS interval had the scope feed active; every hip/turn interval
had it inactive. Native city startup reported **32 supported buildings, 4,800
support nodes, 728 roots, zero quarantines, zero missing geometry, and zero initial
unreachable parts**. Support-node count is not a measured render draw count.

The largest ADS CPU-zone difference is `frame.execute`: median **14.367 / 14.590
ms** for the city versus **4.957 / 5.054 ms** for the control. Declaration medians
are 2.030 / 2.008 versus 1.135 / 1.142 ms. City simulation medians are 2.177 /
2.150 ms; control simulation medians are zero because many faster frames have no
fixed simulation tick. These zone medians must not be added into a synthetic frame.

`frame.execute` wraps graph execution and command recording **before** GPU
submission. It is not a GPU timestamp. Source inspection confirms that camera-hidden
draws remain in shadow submissions, and that visible ADS renders the world through
a second renderer. This suggests a concrete scaling path, but does not isolate a
safe optimization. The [bounded diagnosis](play-city-2026-10-17/cost-diagnosis.md)
records the evidence and the next instrument: per-view draw/caster counts and
per-pass CPU/GPU timings. Removing camera-hidden shadow casters would be incorrect.

## Why this is not a baseline

Loaded samples (GPU utilization at least 10%) across the entire capture, including
startup and warmup, recorded these graphics-clock spreads:

| Capture | Min / median / max MHz | Spread |
|---|---:|---:|
| City 1 | 1440 / 1837 / 1942 | 27.33% |
| Control 1 | 1920 / 1920 / 1942 | 1.15% |
| Control 2 | 1942 / 1942 / 1942 | 0.00% |
| City 2 | 1350 / 1717 / 1942 | 34.48% |

Memory stayed at 7501 MHz in loaded samples. No clocks were pinned and no gate was
weakened. Clock differences preclude a precise attributable regression percentage.
They do not justify treating the observed city ADS timings as meeting the target.

The required standard command was also attempted:

```sh
VK_DRIVER_FILES=/usr/share/vulkan/icd.d/nvidia_icd.json \
  scripts/perf.sh --preset release --sample the-block --frames 600 \
  --width 1920 --height 1080 --commit
```

It **refused before rendering, exit 4**, because Chromium was using 73% CPU at
that later pre-check. No busy-box override was used, no sample report was generated,
and no baseline was filed. The [refusal log](play-city-2026-10-17/scripted-perf-refused.log)
is retained. That scripted mode excludes the generated city in any case; the native
captures above are the evidence about this brick.

## Artifacts and remaining limits

[comparison.json](play-city-2026-10-17/comparison.json) contains distributions,
phase counts, clock samples' reduction, and run timestamps. The same directory
contains compressed raw frame/clock CSVs, per-binary provenance with source and
linked-input hashes, an archive hash manifest, startup logs, and the reusable
[generator/analyzer instructions](play-city-2026-10-17/README.md).
All four retained frame archives were decompressed and reanalyzed; their phase
statistics exactly match the original summaries.

The generator recorded `7d72ad3-dirty`; the dirty state includes documentation
edits and existing scratch notes. Production main-source bytes were unchanged. The instrumentation lives
in a generated copy outside the checkout. That production city tree is equivalent
to `a35e35d` (rebased as `0a323e2`). Later
`6347884` only formats the support helper: all non-whitespace characters were
verified unchanged, and the final target was rebuilt. The manifests identify the
actual binaries rather than attributing them to a later documentation commit.

No sustained-fire or collapse-load timing was measured. Lamp/barrier collision
thresholds remain inferred, added buildings still lack SDF proxies, and the
pre-existing burst replication divergence remains worked around by the deterministic
96-release-per-step cap. None of these gaps is repaired by this report.

The initial harness and a separate read-only cost diagnosis used `gpt-6-sol` at
medium effort. The orchestrator reviewed the changes, added input/binary hashes
and stale-output checks, extended each measured phase to 600 frames, and ran the
captures and archive sensitivity checks. The source diagnosis was useful; it did
not establish a removable redundant pass. No premium or Claude consultation ran.
