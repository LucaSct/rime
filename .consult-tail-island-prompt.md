# Problem: a 5.3 ms serial solve tail in one physics island. Propose the cheapest lever.

Give me YOUR OWN proposal, not feedback on mine. I have deliberately not told you what I plan.

## The engine

Rime, a C++20 game engine. Rigid-body physics: sequential-impulse PGS velocity solver,
`kVelocityIterations = 8`, then `kPositionIterations = 2` NGS position iterations. Contacts become
contact *points* ("constraints"). Bodies are SoA/dense-indexed.

Per step: broadphase -> narrowphase manifolds -> union-find ISLAND partition over the tick's contact
constraints -> wake/skip islands -> `parallel_for` over islands on a job system (one island = one
job, solved start to finish on one worker) -> sequential sleep update -> commit.

Determinism contract (ADR-0026): fixed iteration counts, dense/canonical ordering everywhere,
union-by-smaller-index so a set's root is its lowest dense member; the world hash must be bitwise
identical regardless of how many worker threads ran. Nothing in the solve may read a clock, a
pointer identity, or an unordered container.

Sleeping is ISLAND-WIDE and all-or-nothing:

```cpp
// post-solve velocities, per ACTIVE island k
bool island_can_sleep = true;
for (body i in island k) {
    const bool sleepy = |v_lin(i)|^2 < 0.05^2 && |v_ang(i)|^2 < 0.05^2;   // m/s, rad/s
    sleep_timer[i] = sleepy ? sleep_timer[i] + dt : 0.0f;
    if (sleep_timer[i] < 0.5f /* kTimeToSleep seconds */) island_can_sleep = false;
}
if (island_can_sleep) { for (body i in island k) { asleep[i] = 1; v_lin = v_ang = 0; } }
```

So ONE body moving above threshold keeps every body in its island awake and fully solved.
